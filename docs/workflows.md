# Сценарии и функциональность Bot4VPS Mobile 1.6.0

Документ описывает функциональность Android-приложения Bot4VPS Mobile и её соответствие мобильной Web-панели.

Мобильная Web-панель Bot4VPS является эталоном серверных операций и бизнес-логики. Android-клиент реализует собственный интерфейс и взаимодействует с сервером через Mobile API.

Пользовательские меню и доступные действия определяются сценариями `PanelWorkflows`. Транспортный контракт описывает API-маршруты, поля запросов и проверку значений.

Вход в Android-приложение отделён от Web-авторизации: используется QR-привязка и криптографический ключ устройства. Управление Web-учётной записью непосредственно в APK отсутствует.

## 1. Навигация и основные разделы

Нижнее меню приложения содержит пять разделов:

- **Обзор** — состояние серверов и общая информация.
- **Серверы** — список серверов и управление группами.
- **Сервисы** — управление дополнительными службами и инструментами.
- **История** — журнал событий и история задач.
- **Ещё** — настройки, обновления и сведения о приложении.

Нажатие на вкладку возвращает пользователя к корню соответствующего раздела. В SSH-терминале нижняя навигация скрыта.

Основной экран истории — журнал событий. История задач открывается отдельной кнопкой внутри журнала.

## 2. Обзор и управление серверами

### Обзор

На главном экране отображается до шести серверов. Приоритет имеют серверы с проблемами; при полном обновлении используется случайная выборка.

В строках серверов отображаются CPU, RAM и TCP-пинг до SSH-порта. Для хоста доступны CPU, RAM, сеть и графики в реальном времени.

Обновление данных:
- фоновые замеры сохраняют текущую выборку;
- протяжка вниз формирует новую выборку и перечитывает данные;
- начальная загрузка и автоматическое обновление не изменяют расположение карточек.

В блоке обзора доступны:
- добавление сервера вместо отдельного перехода в «Сервисы»;
- состояние Telegram;
- переход к мониторингу службы.

Очереди и задачи непосредственно в блок обзора не включены.

**Источник сверки:** `dashboard.js`.

### Список серверов

Список поддерживает обновление протяжкой вниз и компактный поиск.

В верхней части расположены добавление серверов и управление группами.

Вся строка сервера открывает его карточку. IP-адрес раскрывается отдельно и копируется соответствующей кнопкой. После копирования отображается уведомление «IP скопирован».

В зависимости от выбранного режима отображения вместо IP могут показываться SSL, uptime, группа или статус сервера.

**Источники сверки:** `servers.js`, Server Settings API.

### Группы

Приложение отображает каталог групп, включая пустые.

Карточки содержат:
- название группы;
- количество серверов;
- переключатель проверки SSL с пояснением.

Редактирование имени и локальной видимости выполняется через диалог. Пустые группы можно удалять.

Настройка видимости действует только на текущем телефоне для выбранной панели. Серверы скрытой группы остаются доступными в общем списке.

Порядок отображения групп отдельно не настраивается.

**Источник сверки:** `groups_panel.js`.

### Настройки групп

Настройки группы представлены единым списком компактных карточек.

Переключатель «Проверять SSL» управляет проверкой сертификатов серверов группы. Эта настройка общая для всех устройств.

Для изменения имени и видимости используется пункт «Редактировать» в меню карточки.

## 3. Сервисы и инструменты

В списках серверов каждого сервиса сохранены фильтры «Все», «Установлен»
и «Не установлен»; отдельная строка выбора групп убрана.
В разделе «Ещё → Инструменты» первым расположен «Мониторинг Bot4VPS».
Графики нагрузки открываются через «Графики серверов» с подписью «История нагрузки».

В «О программе» строки «Версия панели» и «Версия приложения» выровнены
в три общие колонки: названия слева, версии по центру и небольшие кнопки
GitHub справа. Обычные пропорции — примерно 50% / 25% / 25%; при увеличенном
системном шрифте ссылки получают больше места, а названия могут переноситься.
Ссылка автора отображается сразу после
«Автор — » с обычным одиночным пробелом. Репозиторий панели —
`crashdmd/Bot4VPS`, приложения — `crashdmd/Bot4VPS-Mobile`.
Описание версии открывается на вкладке обновлений.

### Общие проверки серверов

Раздел доступен через **Сервисы → Проверки серверов**.

На отдельном экране расположены две проверки:
- Пинг.
- SSL-сертификаты.

При открытии вкладки список результатов скрыт. В блоке кнопки проверки
под временем последнего успешного запуска мелким шрифтом показана сводка:
для SSL — действуют, скоро истекают, истекли и ошибки; для пинга — в сети,
офлайн, неизвестно и ошибки.

Кнопка «Результаты последней проверки» появляется при наличии сохранённых
данных и открывает список. Новая проверка показывает актуальные результаты.
Когда список открыт, в шапке доступна сортировка по задержке пинга или числу
дней до истечения сертификата в обоих направлениях. Ошибки без численного
результата остаются в конце списка.

Протяжка вниз перечитывает результаты, а кнопка запускает новую проверку.

Результаты пинга и SSL независимы. Повторный запуск той же проверки блокируется до завершения предыдущего.

Таймаут пинга не отображается как успешная задержка. При ошибках сохраняются предыдущие результаты.

**Источники сверки:** `monitor/check/online`, `monitor/check/ssl`, `servers/{id}/ping`.

### Файлы

Раздел содержит вкладки:
- Compose;
- SSH-ключи;
- Скрипты.

Поддерживается переход по каталогам. Возможность создания и загрузки файлов зависит от текущего каталога.

При открытии редактора содержимое файла загружается автоматически.

**Источники сверки:** `files.js`, `editor.js`.

### Docker

Доступны контейнеры, образы и Compose-проекты.

При выборе развёртывания сохраняются его `source` и `key`. Файлы проекта можно просматривать и редактировать непосредственно в редакторе.

Исключение и возврат проектов доступны из контекстного меню.

**Источники сверки:** `docker.js`, Compose model.

### WireGuard

Отображаются профили WireGuard и доступные действия для каждого профиля.

QR-код и конфигурация сразу открываются для просмотра и сохранения. Поддерживается экспорт управляемых профилей.

**Источник сверки:** `wireguard.js`.

### 3x-ui

Мобильный интерфейс предоставляет следующие возможности:

- открытие адреса панели во внешнем браузере после подтверждения;
- просмотр фактического состояния BBR;
- установка и удаление SelfSNI;
- просмотр и копирование параметров Reality;
- выпуск HTTPS-сертификатов для домена или IPv4;
- продление и отзыв сертификатов с выбором владельца acme.sh или certbot;
- импорт и экспорт базы;
- просмотр вывода выполняемых задач.

Недоступные действия отключены. Вместо произвольного ввода параметров используются явно заданные поля.

В блоке доступа нет отдельной строки для пути панели.

**Источники сверки:** `3xui.js`, Services API.

### Скрипты

Поддерживаются поиск, запуск, редактирование и удаление скриптов.

При запуске передаются только видимые и непустые параметры. Парольные поля маскируются.

После принятия задачи приложение открывает её вывод.

**Источник сверки:** `scripts.js`.

### Очереди

Раздел доступен через «Сервисы».

Действия привязаны к конкретному серверу. Отображаются текущие и ожидающие задачи.

**Источники сверки:** Queues API, Task Manager.

## 4. История, события и аудит

### История задач

История задач открывается из журнала событий отдельной кнопкой.

Доступны:
- просмотр задач и их вывода;
- фильтры;
- периодическое обновление вывода;
- отмена задачи с подтверждением.

Очистка истории задач требует подтверждения на текущем экране и распространяется на все серверы. Активные задачи при этом продолжают выполняться.

### События

Отображается список событий с подробностями.

При открытии события оно отмечается прочитанным. Подробности показываются в прокручиваемом диалоге.

Очистка журнала требует подтверждения и выполняется непосредственно на экране событий.

**Источник сверки:** `monitor.js`.

### Аудит

По умолчанию отображаются события за последние семь дней.

Доступны периоды:
- 24 часа;
- 7 дней;
- 30 дней;
- 90 дней;
- произвольный диапазон через календарь.

Поиск выполняется с задержкой 350 мс. Фильтры `facets` показывают количество записей и учитывают исторические серверы.

Загрузка использует курсор с неизменными границами периода и кнопку «Показать ещё».

Подробности записи разбирают вложенный `record` и могут включать:
- автора;
- сервер;
- время начала и завершения;
- длительность;
- ошибки;
- параметры операции;
- техническую хронологию.

При наличии связанных данных доступны вывод задачи, соответствующее событие и переход к графику.

Состояние `incomplete` не отображается как выполняющаяся операция.

Список обновляется протяжкой вниз. При первоначальном открытии сервер автоматически не выбирается. Явно установленный фильтр остаётся видимым и снимается пользователем.

**Источники сверки:** `audit.js`, `audit_query.py`, Audit API.

## 5. Мониторинг Bot4VPS и терминал

### Мониторинг службы

Отображаются CPU, память и сеть с подписями осей и времени. Сетевой график содержит две линии с легендой.

Кнопка «Журнал службы» открывает поток `journalctl` через SSE.

Особенности журнала:
- хранение последних 500 строк;
- автоматическое переподключение при обрыве;
- закрытие соединения при уходе с экрана;
- кнопки «Остановить обновление» и «Продолжить обновление» для управления потоком;
- размер шрифта 11 sp.

Счётчик ошибок событий в кнопке журнала отсутствует.

**Источники сверки:** `monitor.js`, `system.py`, `/api/system/journal`.

### Метрики

График объединяет Load 1, память и диски на общей временной шкале.

Проценты отображаются по левой оси, Load 1 — по правой.

Взаимодействие с графиком:
- касание показывает значения всех метрик выбранной пробы;
- удержание и движение позволяют просматривать соседние точки;
- поддерживаются панорамирование, масштабирование щипком и кнопками;
- доступны сброс масштаба и снятие выбранной точки.

Предусмотрены периоды, календарь, метки операций и доступности, разрывы данных и переход к аудиту.

Для перехода из аудита используется диапазон ±1 час.

Последний диапазон обновляется, пока экран видим. Фиксированные даты и выбранный масштаб не сдвигаются при обновлении.

### SSH-терминал

В терминале нижние вкладки скрыты.

Предусмотрены Ctrl и дополнительные клавиши. Ctrl изменяет следующую вводимую клавишу. Дополнительные клавиши расположены в одной горизонтально прокручиваемой строке над клавиатурой.

При выходе клавиатура скрывается.

SSH-сессия и вывод сохраняются до пяти минут после ухода с экрана. Повторное открытие терминала того же сервера продолжает прежнюю сессию.

Сворачивание и поворот экрана также сохраняют сессию. Кнопка завершения в шапке закрывает её немедленно.

После пяти минут открывается новая сессия. При разрыве сети или завершении процесса Android соединение может закрыться раньше.

**Источники сверки:** `metrics.js`, `chart.js`, `timeline.py`, Terminal API.

## 6. Настройки и оформление

### Настройки

Настройки организованы на едином экране с категориями:
- параметры;
- безопасность;
- Telegram;
- уведомления;
- данные;
- обновления;
- сведения.

Карточки имеют иконки, заголовки, разделители и единое оформление кнопок. Пояснения размещаются рядом с соответствующими элементами управления.

Настройки Telegram и телефона раскрываются по нажатию. Уведомления встроены в соответствующую категорию, отдельной ссылки на журнал событий в них нет.

**Источник сверки:** `settings.js`.

### Оформление

По умолчанию используется тёмная тема. Также доступны светлая и синяя темы.

Выбор темы находится в настройках приложения. Отдельный блок темы из раздела «Ещё» удалён.

Тема сохраняется локально на телефоне и не синхронизируется с Web-панелью.

**Источники сверки:** `layout.css`, `settings.js`.

### Обновления

На экране «Обзор» проверка обновлений показывает:
- уведомление об актуальной версии;
- либо окно с описанием изменений и кнопками «Установить обновление» и «Отмена».

Переходить в настройки для установки не требуется.

Основная кнопка последовательно выполняет проверку, установку и отображение выполнения.

Проверка использует `update/check` и `update/state`, не запрашивая `maintenance`.

Перед установкой сохраняется протокол `maintenance begin/cancel/force`. После перезапуска проверяется результат обновления.

В разделе обновлений доступны два блока:

- **Панель Bot4VPS** — проверка и установка обновления сервиса.
- **Приложение Bot4VPS Mobile** — проверка и скачивание APK.

Автоматические проверки включаются отдельно.

Суточный интервал автоматической проверки APK начинается после успешного ответа источника. После сетевой ошибки ручную проверку можно повторить сразу. Сборка с тем же номером версии и большим `versionCode` также считается обновлением; подпись должна совпадать с установленным приложением.

Проверка мобильного обновления использует источник из исходников приложения на GitHub. Перед системной установкой проверяются размер, SHA-256, пакет, версия и сертификат подписи APK.

В приложении также доступны описание версии и информация об откате серверной части.

**Источники сверки:** `monitor.js`, `maintenance.js`, `MobileReleaseSource`.

### Порт и HTTPS

Изменение порта и настроек HTTPS предусматривает:
- подтверждение перезапуска;
- сохранение ожидающей операции;
- проверку прежнего состояния;
- проверку нового адреса;
- повторный вход при изменении адреса;
- загрузку сертификата перед его применением.

**Источник сверки:** `settings.js`, `web_port`, `web_tls`.

### Telegram

Поддерживаются включение и выключение Telegram, настройка токена и получателя, проверка доставки.

Кнопка «Проверить доставку сообщения» видна только при включённом и работающем
боте. Она запускает отправку напрямую: успешная отправка подтверждается
всплывающим сообщением «Тестовое сообщение отправлено», ошибка отображается
в диалоге с полным текстом и кнопкой «Ок».

Пустое поле токена сохраняет существующее значение.

**Источники сверки:** `settings.js`, System API.

## 7. Подключение и безопасность

### Подключение

При удалении привязки удаляются ключи устройства и сохранённые секреты
операций этой панели. PIN и привязки других панелей сохраняются.

Приложение использует отдельный HTTPS Mobile API и привязку устройства через доверенную Web-панель.

При запуске отображается текущий адрес панели. Сменить адрес или подключиться к другой панели можно непосредственно во время ожидания.

Попытка подключения ограничена 10 секундами. При отсутствии ответа отображается подсказка о сетевой ошибке и возможность повторить попытку.

При смене адреса предыдущая попытка отменяется.

Привязка требует подтверждённого ключа устройства независимо от состояния Web-авторизации. После регистрации повторный Web-логин не требуется.

TLS-ключ сервера закрепляется на телефоне. Передача кода первоначальной привязки по HTTP допускается только в доверенной сети.

Подробности приведены в [инструкции по подключению](connection.md).

### PIN и биометрия

PIN приложения состоит из четырёх цифр.

Ввод, создание и смена PIN используют отдельный экран с точками и встроенной цифровой панелью. Системная клавиатура не вызывается.

После четвёртой цифры выполняется соответствующее действие. При повторном вводе нового PIN точки сбрасываются и заполняются заново в том же ряду.

При смене PIN сначала проверяется текущий.

После включения блокировки появляется возможность настроить биометрию:
1. Ввод текущего PIN.
2. Системное подтверждение отпечатка.
3. Сохранение биометрической настройки.

Криптографическая операция с данными выполняется после подтверждения. Ошибки Android не подменяются ошибкой неверного PIN.

Отмена и устаревшие результаты не меняют новую попытку. Повторные ошибки PIN включают сохраняемую задержку.

При обновлении с версии 1.1 прежний пароль или биометрия используются для подтверждения создания PIN. До завершения процедуры содержимое приложения скрыто.

### Просмотр мастер-ключа

При включённой защите приложения последовательность следующая:

**Биометрия или повторный PIN → «Личность подтверждена» → «Посмотреть мастер-ключ» или «Отмена».**

После выбора просмотра сервер выдаёт одноразовый challenge. Телефон подписывает его двумя ключами, Mobile API проверяет подписи и возвращает мастер-ключ.

Повторный PIN или биометрия на этом этапе не требуются. Первое защищённое использование также не требует Web-2FA.

Подтверждение временное, не сохраняется и очищается при отмене или уходе в фон.

При выключенной защите используется пароль администратора и TOTP либо код Telegram непосредственно в приложении. Оба фактора проверяет Mobile API.

Если Keystore недоступен, предусмотрен альтернативный просмотр через Web с паролем и вторым фактором либо через CLI.

Приложение блокируется через 30 секунд после ухода в фон. Возврат раньше этого срока не требует повторного входа. Каждый новый уход в фон начинает отсчёт заново. После уничтожения процесса требуется новая разблокировка.

Эти 30 секунд не ограничивают срок подтверждения личности на открытом экране. Показанный мастер-ключ скрывается немедленно при сворачивании и через 30 секунд отображения. Запоздавшие ответы не показываются.

Защищённое содержимое скрывается на снимках экрана и в списке последних приложений.

Подробности криптографической реализации приведены в [описании безопасности](security.md).

### Уведомления телефона

Уведомления телефона поступают независимо от выключателя и интервала доставки Telegram.

Начальная история событий не рассылается. Повторные идентификаторы событий отсекаются.

## 8. Резервное копирование и восстановление

Резервные копии доступны в разделе «Сервисы» после 3x-ui, а также в карточке сервера.

Общий пинг и SSL-проверка доступны через «Сервисы → Проверки серверов» и меню выбора сервиса. Повторный запуск выполняется на том же экране.

Сценарий восстановления:

**Цель → Архив → Проверка состава → Серверный план → Подтверждение.**

Защитная копия перед применением включена по умолчанию.

Применение использует подготовленный план v3. При повторном запросе после неопределённого ответа сохраняется `request_id`.

Пароль архива остаётся на Web-панели.

## 9. Управление службой Bot4VPS

Перезапуск Bot4VPS запускается из раздела мониторинга службы.

После подтверждённого восстановления связи окно закрывается через секунду.

При ошибках или необходимости повторной авторизации приложение сохраняет соответствующие действия для пользователя.

## 10. Общие правила интерфейса

В приложении используются единые правила отображения и взаимодействия:

- Растяжение карточек происходит только в результате пользовательской протяжки. Начальная загрузка, автоматическое обновление и кнопка обновления не сдвигают блоки.
- Переходы между экранами используют затухание длительностью 150 мс.
- Поиск выполнен как общий компактный элемент высотой 40 dp.
- Копирование IP и адресов сопровождается уведомлением.
- Настройки используют единые карточки с пояснениями и общим оформлением кнопок.
- Категории Telegram и телефона раскрываются по нажатию.
- Очистка журнала событий и истории задач находится в шапках соответствующих экранов.
- Переходы между событиями и задачами занимают всю строку и сопровождаются пояснением под названием.
- Подробности событий показываются в прокручиваемом диалоге.
- В аудите нет плашки «Есть изменения» и автоматически выбранного сервера. Явный фильтр остаётся видимым и снимается пользователем.
