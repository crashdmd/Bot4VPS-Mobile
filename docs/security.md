# Безопасность Bot4VPS Mobile

Bot4VPS Mobile использует отдельный HTTPS Mobile API и собственную систему криптографической аутентификации устройств.

Мобильное приложение не использует Web-cookie, пароль администратора или Web-сессию для обычного подключения. Доступ предоставляется только ранее привязанным устройствам с действующими криптографическими ключами.

Основные механизмы безопасности:
- отдельный HTTPS API;
- привязка устройства с проверкой ключа сервера;
- криптографическая аутентификация телефона;
- короткоживущие мобильные сессии;
- локальная защита приложения PIN-кодом и биометрией;
- отдельное подтверждение просмотра мастер-ключа;
- аудит действий мобильных устройств.

## 1. Архитектура доступа

Web-панель и Mobile API используют разные механизмы аутентификации.

Web-панель отвечает за настройку мобильного доступа, регистрацию устройств и управление привязками.

Mobile API проверяет криптографические подписи зарегистрированного телефона. Web-авторизация и её второй фактор не используются при обычном входе в мобильное приложение.

Отключение Web-авторизации не отключает проверку ключей мобильных устройств. Mobile API сохраняет собственную аутентификацию независимо от настроек Web-панели.

Мобильные запросы используют отдельные маршруты API. Маршруты управления Web-авторизацией и привязками не доступны через Mobile API.

## 2. HTTPS и проверка сервера

Mobile API принимает подключения только по HTTPS. HTTP для API запрещён в AndroidManifest и сетевой конфигурации приложения.

При первоначальной привязке приложение получает отпечаток открытого ключа сервера. Он сохраняется на телефоне и используется для проверки последующих соединений.

При несовпадении ключа сервера приложение отклоняет подключение до передачи секрета привязки.

Приложение:
- не доверяет произвольным самоподписанным сертификатам;
- не отправляет Web-cookie;
- отключает перенаправления;
- проверяет соответствие адреса и порта сохранённой привязке.

Для локального сервера не обязательны домен, белый IP, Let's Encrypt или установка собственного центра сертификации на Android. Серверный ключ создаётся автоматически, а его отпечаток передаётся при привязке.

Первоначальную передачу QR-кода или текстового кода выполняйте в доверенной сети либо через защищённый канал доступа к Web-панели.

## 3. Привязка устройства

При создании привязки сервер формирует одноразовый секрет и данные подключения.

QR-код и текстовый код содержат:
- адрес Mobile API;
- одноразовый секрет;
- отпечаток открытого ключа сервера.

Привязка действует 10 минут и расходуется при первой успешной регистрации устройства.

Повторное использование секрета отклоняется, в том числе при одновременных попытках регистрации через QR и текстовый код.

При регистрации:
1. Приложение получает данные подключения.
2. Проверяет ключ сервера.
3. Создаёт ключ устройства в Android Keystore.
4. Передаёт открытый ключ серверу для регистрации.
5. Сервер сохраняет открытый P-256 ключ телефона и завершает привязку.

Закрытая часть ключа устройства не экспортируется из Android Keystore.

Секрет привязки хранится на сервере в виде хеша. Коды, ключи и сессии не записываются в аудит.

При отзыве устройства сервер удаляет его доступ и завершает активные потоки и терминальные соединения.

## 4. Криптографическая аутентификация

Для подтверждения запросов используется криптография на основе эллиптических кривых P-256.

Сервер проверяет подписи зарегистрированного устройства. Для защиты операций используются одноразовые challenge, связанные с конкретным устройством и выполняемой операцией.

Обычная мобильная сессия не заменяет криптографическую проверку устройства.

При использовании защищённых операций сервер проверяет соответствующие подписи и срок действия challenge. Повторное использование или истечение срока действия подтверждения приводит к отказу.

Секретные части ключей не передаются серверу. На сервере хранятся открытые ключи, необходимые для проверки подписей.

## 5. Мобильные сессии

Мобильная сессия действует 15 минут.

Для поддержания активного SSH-терминала приложение автоматически продлевает доступ в том же WebSocket, сохраняя соединение и удалённый SSH-процесс.

Если продление не удалось до окончания срока действия сессии, сервер закрывает соединение.

Кнопка «Подключить» выполняет повторное подтверждение ключа телефона.

Если владелец отозвал устройство, для дальнейшего доступа потребуется новая привязка.

Старые версии APK, не поддерживающие продление сессии, ограничены первоначальным сроком её действия.

## 6. Локальная защита приложения

Для защиты доступа к приложению предусмотрен отдельный PIN-код из четырёх цифр.

PIN вводится и подтверждается на специальном экране с цифровой клавиатурой. После его настройки можно включить биометрическую разблокировку средствами Android.

При включении биометрии сначала требуется подтверждение текущим PIN, затем системная проверка биометрии.

Автоматическая блокировка происходит через 30 секунд после перехода приложения в фон. Если пользователь возвращается раньше, повторный вход не требуется. Каждый новый переход в фон начинает отсчёт заново.

При уничтожении процесса Android потребуется новая разблокировка.

PIN защищает локальный доступ к приложению. Он не заменяет серверную криптографическую аутентификацию устройства.

## 7. Защищённый просмотр мастер-ключа

Просмотр мастер-ключа является отдельной защищённой операцией.

При включённой локальной защите требуется повторный PIN или биометрия. При выключенной защите используются пароль администратора и TOTP либо код Telegram, если TOTP не настроен.

### Ключи операции

При привязке телефона создаётся отдельный P-256 ключ подписи в Android Keystore. Его закрытая часть не экспортируется.

При первом защищённом просмотре регистрируется дополнительный ключ операции. Он создаётся средствами Java, а его закрытая часть хранится в зашифрованном виде в приложении.

При регистрации ключа защищённого просмотра сервер проверяет три подписи: ключа привязанного устройства, отдельного ключа операции в Android Keystore и ключа, закрытая часть которого защищена локальным PIN или биометрией.

При последующем просмотре challenge подписывается двумя ключами операции: ключом Android Keystore и ключом, расшифрованным после PIN или биометрии. Ключ привязанного устройства используется для аутентификации мобильной сессии.

Обычный ключ мобильной сессии сам по себе не разрешает просмотр мастер-ключа.

### Защита ключа операции

Для PIN используется следующая схема:

- PBKDF2-HMAC-SHA256 с 600 000 итераций;
- отдельный неэкспортируемый AES-256 ключ Android Keystore;
- зашифрованное хранение закрытого ключа операции.

При биометрической защите расшифровка выполняется через ключ Android Keystore, требующий системного подтверждения биометрии.

Ключ подписи привязанного устройства сам по себе не требует биометрического подтверждения. Локальная защита применяется к расшифровке отдельного ключа операции.

### Подтверждение просмотра

После локальной проверки личности приложение показывает экран «Личность подтверждена» с действиями «Посмотреть мастер-ключ» и «Отмена».

Challenge запрашивается и подписывается только после выбора просмотра. Повторный ввод PIN или биометрия на этом шаге не требуются.

Одноразовый challenge:
- действует 30 секунд после запроса;
- привязан к устройству и операции;
- не может быть использован повторно;
- отклоняется после истечения срока действия.

Ожидающее подтверждение имеет ограниченный срок и лимит попыток.

Запросы выполняются через отдельные маршруты `/api/masterkey/phone/…`, требующие проверенную сессию устройства. Web-cookie и обычные заголовки не заменяют эту проверку.

### Отображение и очистка

Мастер-ключ не сохраняется приложением в постоянном хранилище.

Он скрывается:
- через 30 секунд после отображения;
- сразу при переходе приложения в фон;
- при закрытии окна просмотра.

Снимки экрана во время просмотра запрещены.

Если Keystore недоступен, приложение предлагает альтернативный просмотр через Web с паролем и вторым фактором. Если подтверждение недоступно, приложение предлагает перейти к настройкам защиты или использовать CLI.

При переходе в аутентификатор или Telegram для получения кода текущий шаг подтверждения сохраняется, а введённые поля очищаются.

### Буфер обмена

Скопированное значение сохраняется до окончания исходного 30-секундного срока просмотра.

При явном закрытии окна буфер очищается, если его содержимое не было заменено другим приложением.

Android может ограничивать доступ к буферу в фоне. В этом случае просроченное значение очищается при возвращении в приложение.

## 8. Серверные ключи и сертификаты

Ключ и сертификат Mobile API хранятся в:

`data/mobile-api/`

Права доступа:
- каталог — `0700`;
- файлы — `0600`.

При переносе или восстановлении сервера эти файлы необходимо сохранять.

Продление сертификата сохраняет ключ и не требует повторной привязки устройств.

Замена самого ключа сервера требует проверки нового отпечатка и повторной привязки телефонов.

Изменение порта или HTTPS-адреса Web-панели само по себе не меняет адрес Mobile API.

## 9. Аудит

Система записывает события, связанные с мобильным доступом:

- изменение настроек API;
- ошибки применения настроек;
- создание кода привязки;
- успешную привязку;
- отзыв доступа;
- успешный и неуспешный просмотр мастер-ключа.

Действия мобильного приложения обозначаются источником `phone`.

Для обычного Web-подключения заголовок `X-Bot4VPS-Client: phone` является только меткой аудита и сам по себе не предоставляет доступ.

Для проверенного телефона источник подтверждается сессией устройства. В аудите сохраняются идентификатор устройства, роль администратора и IP-адрес.

Просмотр мастер-ключа записывается как `secret.masterkey_view` с указанием источника. Сам мастер-ключ, пароль администратора и коды подтверждения в аудит не записываются.

Опрос статуса и сохранение настроек без изменений не создают повторных записей.

## 10. Ограничения безопасности

Мобильная защита состоит из нескольких независимых уровней: HTTPS и проверка сервера, криптографическая аутентификация устройства, локальная блокировка приложения и отдельное подтверждение чувствительных операций.

PIN и биометрия защищают доступ на телефоне, но не заменяют контроль доступа к самому серверу. Безопасность Web-панели, Mobile API и операционной системы сервера также зависит от правильной сетевой настройки, управления привилегиями и защиты учётных данных администратора.
